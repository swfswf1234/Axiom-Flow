# v0.3 架构就绪审计

设计状态：Accepted
实现状态：Completed
最后更新：2026-07-27

## 结论

v0.2 已完成单篇 PDF 的审阅与发布闭环，但不宜直接承载批量处理和学习交互。全量 23 项
测试证明主路径可运行，尚未覆盖任务级预算、幂等命令、并发领取、审阅历史和长任务恢复。

## 已确认缺口

- 文档的 `Current（目标设计）` 混合当前事实与未来目标，人工与 Agent 无法直接判断落地程度。
- `BailianProvider.calls` 在应用进程内累计，预算和 `ParseRun.model_calls` 不是任务级数据。
- 再次抽取会替换候选和关系，不能保留抽取版本与审阅事件。
- HTTP 路由、文件操作、应用编排和领域规则集中在少数模块，跨层使用松散字典。
- 解析和抽取占用 HTTP 请求直至结束，缺少持久任务、租约、进度、取消和可靠恢复。
- 依赖混合 v0.2、Legacy 与未来候选能力；远端尚无自动化门禁。

## 处理决定

本轮升级为 v0.3 架构重建。采用 MySQL 持久任务和独立 Worker，允许 `/api/v1` 破坏性升级，
通过增量迁移建立新数据结构。开发数据可以显式重建，但普通启动和迁移不得静默删除数据。
正式解析质量评测仍等待数学样本，不与确定性的架构重构互相阻塞。
