# ADR 0021：分层确定性测试架构

状态：Accepted
日期：2026-07-30
领域：工程治理
决策阶段：v0.3
取代：—
被取代：—

## 背景

现有 `tests/` 同时包含纯单元测试、文档与架构治理、MySQL 集成、进程内主链和公开 fixture 回归，
但全部平铺且没有稳定分层。全量 Pytest 能保护当前契约，却不能让开发者快速区分失败属于业务规则、
适配器、跨模块工作流还是实际进程装配。独立 API 与 Worker 启动仅作为历史人工验收执行，未形成
持续门禁。

测试与评测还需要保持边界：确定性测试保护已采纳契约，真实教材、外部模型、提示词和质量采纳由
冻结评测回答。用测试调用真实模型会破坏可复现性，用评测替代工程回归则无法稳定保护生产链路。

## 决定

`tests/` 按 `unit`、`contract`、`integration`、`system` 和 `smoke` 五层组织，每项测试恰好属于一层。
公共 fake、builder 和进程辅助放在 `tests/support`，不承载测试用例。目录是测试层级的事实，Pytest
marker 由收集钩子自动附加并严格校验。

所有自动测试禁止访问外部模型和公网。单元与契约测试不依赖 MySQL；集成与系统测试只使用隔离测试
库和临时文件；系统测试使用确定性假供应商经过公开应用入口验证闭环。冒烟测试显式迁移独立 smoke
数据库，启动真实 ASGI 与 Worker 命令入口，只验证装配、健康、静态资源和空队列轮询，不提交模型
任务。

每个 pull request 和 `main` push 依次执行静态检查、快速测试、集成/系统测试和进程冒烟。覆盖率按
测试层生成基线报告，但首轮不设置统一百分比阈值；关键契约仍以风险场景和状态转换完整性验收。

`evaluation/` 继续负责冻结真实样本、预算、人工评分和候选采纳。公开 fixture 可以由系统测试执行
确定性回归，但其通过只证明工程契约稳定，不证明外部模型质量。

## 后果

开发者可以按风险选择最小门禁，CI 失败也能直接定位层级。真实进程入口会在每次 CI 中得到验证，
同时不会引入模型密钥、版权样本或不确定网络调用。目录迁移需要一次性同步源码文件头、设计文档、
code-map、Agent 路由和测试命令；后续新增测试必须先选择唯一层级。

覆盖率在形成稳定基线前只提供盲区证据，不能单独作为质量结论。需要引入硬阈值时必须基于现有报告
另行决定，不得为了提高百分比增加无断言价值的测试。
