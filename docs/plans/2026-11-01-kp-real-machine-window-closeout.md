> 所以它们的在册位置是本案的前置闸门，而不是第七枚 todo 行。

## 目标与成功标准

1. 一枚窗口跑完有结论：一本书（默认 b05）的整本梳理产出可在 `af_kp` 与根侧 8903 两侧读回，两侧逐节对账有读数。
2. 「验收判据」17 条的**真机读数**逐条落表（不是用例名，是现场读数），本案把缺读数的条目点名。
3. 每笔梳理调用在共享 `qed_llm_calls` 留一行账，且 `service`／`task`／`step` 三键的实测值域与 `KA-23` 一致。
4. 闸门清单逐条了结：A 档在发令前出裁并落地，B 档在窗口内取到定档读数，C 档给出另批去向。
5. 两枚上游壳的关闭条件成立或明文欠着：`PLAN-025`／`PLAN-026` 各自的「关闭与归档」按本案 W10 的判定推进，
   残余（8903 界面、8900 拉取式提升作业、根侧 `DEFECT-026`）有明确去处，不留模糊的「差不多完成」。

## 范围与非目标

**范围**＝窗口规程（发令 → 冻结件 → 驱动 → 取证 → 复跑）、D 类三必答（备份、回滚、逐次批准）、闸门清单的
落地位（A 档三条随本案：`R7`／`R11` 有文档与码改落地腿，`R17` 只做窗口前体检）、两壳的关闭与台账迁移。

**非目标**＝① 不改四表形状、不新增列与域值（PLAN-024 封闭，ADR 0016）；② 不新增或改写任何判据——需要新形态时
先改 `docs/design/knowledge-analysis.md` 的条文再动码（PLAN-025 前置条件 2 同轴）；③ 不做 8903 确认界面与
8900 提升作业的实现（归根仓库）；④ 不在本案内解禁 MySQL 层 `QED_TEST_MYSQL=1`（用户口径：业务库 `qed` 保持为空，
解禁需另行出裁）；⑤ 不代根侧摘它的台账行，也不碰根仓库与 QED-Tracker 的任何文件。

## 验证与验收

- **读数可指认**＝每一轮的每条判据读数都写成「判据号 → 现场值 → 与用例读数的差」三件，缺读数的判据在本案点名而不是默认通过。
- **两侧对账**＝库侧（`GET /api/v1/books/{book_id}/kp`、`GET …/kp-jobs/{gen_batch}`）与根侧屏上（8903）逐节比对；两侧不一致即判未达成，先归因再裁。
- **零改形状自证**＝窗口前后 `af_kp`／`af_operations` 列数与索引名逐名相等（真库 `SHOW CREATE TABLE` 双份留档），`qed_llm_calls` 未被本组件 ALTER。
- **账目齐**＝一轮调用笔数与账面行数逐轮相等（一次调用一条账，`KA-23`），并给 `step` 实测值域。
- **门禁**＝`pytest tests -q` ＋ `ruff check src tests scripts`，本案每一轮发令前后各一次；MySQL 层仍不含（`QED_TEST_MYSQL=1` 未解禁）。
- **不隐式执行**＝任何「发令」都要用户单独批准，批准原文随读数留档本壳。

## 回滚

- **行为**＝停用梳理通路（形态＝槽位名置空或配成闭集外名字 ⇒ `POST /kp-jobs` 当场 503，零写入）；这条路径的**实测可达性属 W2**，实测前不得当作已具备。
- **数据**＝按 W5 的备份重放 `af_kp` 与 `af_operations` 两表（窗口只写这两表＋共享账表），产物目录内 `kp/` 长文按只读清单人工处置；共享 `qed_llm_calls` 的追加行不做反向清理（`KA-17` 同轴——不回滚账）。
- **代码**＝W2／W3 的落地件（A 档里只有这两条有码改与文档改判腿）可逐条 `git revert`；本案自身零 DDL、零迁移，回滚不涉及库面结构动作。
- **失败轮**＝可重试（真机窗口在册裁决）：一次失败不改变判据，也不得为了「跑通」去改业务参数绕开宿主容量问题——容量类问题按归因写给负责面。

## 关闭与归档

- 关闭判据＝W6 与 W8 两轮读数齐备且闸门清单逐条有去向（A 档了结、B 档给了裁值或另批、C 档有去处）；W9 待裁不阻关闭，但必须在关闭结论里写明「未跑且为什么」。
- 两枚上游壳的关闭：本案给出它们的真机读数面后，`PLAN-025`（关闭条件＝17 条判据全部有读数）与 `PLAN-026`（关闭条件＝W1 真机读数齐备）各按自己的关闭判据翻状态；本案不代替它们判定 S 项，只交付读数与欠账去向。
