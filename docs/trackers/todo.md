## 规则

- **三列语义与列界**（[ADR 0013](../adr/0013-ledger-row-three-elements.md)）：
  - `任务`＝**任务描述**：这件事到底做什么，按承载计划的工作项列出范围（哪几步、落哪张表/哪个
    端点/哪个模块），不写进度与裁决史，**不放文档链接**（链接只登记在「承载」列）；跨项目入站请求的
    `**请求接收（来源仓库 REQ-xxx）**` 标记写在本列句首。
  - `成功标准`＝**完成时的具体终态**（≤80 字）：谁做什么、什么落哪张表/哪个端点/哪个产物，读者
    不必打开别处文档就知道这件事交付什么；一经评审固定，不因进度推进而改写。**禁写验收流程措辞**
    （守护禁词 `门禁`/`收口`/`全绿`/`成文` 与 `S1~S6` 形壳内判据区间引用——它们属于计划壳
    「验证与验收」节）。写不出成功标准的诉求不得成为任务行（A 类小改不入台账，以 git 提交与
    验证记录承接）；长期行写退出/立项条件，主线聚合行写其支线终态的合取。
  - `承载`＝**唯一承载文档指针**：**恰好 1 个** markdown 链接、**不含任何自然语言**（守护剥去链接与
    分隔符后要求残余为空，且链接数 == 1）。指向本篇即本行的事实源：计划镜像行＝其自身壳（链接文本＝壳
    H1 标题，标题与状态由镜像守护逐字比对）；支线行＝其 `../plans/*.md` 承载壳；长期行＝其治理文档。
    `design/`/`architecture/` 等被涉及的文档**不在本列登记**，顺承载文档的「关联设计／关联 ADR」跳。
    现状与描述一律活在指向的那一篇里。
  - **行内禁日期**：三列剥去 markdown 链接目标后不得出现 `YYYY-MM-DD` 字面量。
- **一任务一承载**（[ADR 0006](../adr/0006-ledger-plan-carrier-contract.md)）：每个支线行的承载计划
  引用**只写在「承载」列的那一个链接上**（`../plans/*.md`），且该计划的「关联 Tracker」
  登记了本行 ID，或计划内含 `## 承载 <本行ID>` 节；长期行免承载；主线聚合行必须列全支线行 ID。
- **一任务一行**（[ADR 0011](../adr/0011-ledger-one-row-per-task.md)）：跨项目入站请求与其专属承接计划
  不拆两行——由计划镜像行（`PLAN-*`）单行承载，
  请求号写在该行「任务」列的 `**请求接收（来源仓库）**` 标记内；共享计划下的多个
  任务仍各自成支线行并引用同一承载。
- **进度单源**：日期化进度、现状与证据只写入承载文档；本表行不跟现状，跨档时才改「状态」列，
  收口时整行原子迁移到 [completed.md](completed.md)，历史下沉承载计划「台账历史归档」节。
- **ID 前缀**：`ARCH`=主线/支线实现；`REQ`=跨项目请求；`PLAN`=计划类（必有 `plans/` 正文）。
  `DEFECT`=退役前缀：不再新增，新缺陷登记为支线行挂承载；存量 ID 保留至自然关闭。
- **类别** `主线 / 支线 / 长期`；主线=聚合行与计划类行，支线=可独立收口，长期=无终态。
- **状态** `Open / In Progress / Blocked`（台账唯一的进度信号，粗粒度三值；细节看承载指针指向的壳）；
  支线行同时 In Progress ≤3（超出须先收口或改判，用户
  可显式豁免）；Blocked 的证据、恢复条件与责任位置写进承载计划，本表只在「任务」列末尾留一句
  阻塞因由。`PLAN` 行状态与计划正文 `状态：` 逐字一致（契约测试守护），故可为 `Accepted / In Progress /
  Blocked`。
- **排版**：按「轮次 → 阶段」分节，每节一句推进顺序；跨项目请求以
  `**请求接收（来源仓库）**` / `**请求发出（目标：仓库名）**` 粗体标记，写在「任务」列。
  计划镜像行的壳链接登记在「承载」列（链接文本＝壳 H1 标题），「任务」列只写范围描述。
- Plan 行镜像 `docs/plans/` 活跃计划正文（「承载」列链接文本＝壳 H1 标题、「状态」列与正文 `状态：` 逐字一致、壳的关联 Tracker 登记本行 ID）。
- **收口顺序**（缺任一项视为未收尾）：① 结论写入承载文档 → ② 本行关闭并原子迁移 →
  ③ [completed.md](completed.md)（判据与读数在此安家）→ ④ `plans/index.md` 登记 Retain/Delete →
  ⑤ `project-status.md` 刷新 → ⑥ 全量门禁。
- 涉及子项目改造的请求在本表登记并标注目标仓库；根仓库不直接修改子项目文件
  （见[跨项目协作流程](../standards/cross-project-collaboration.md)）。
