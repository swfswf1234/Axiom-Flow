# 测试架构与门禁

状态：Current
最后更新：2026-07-30
治理对象：测试职责、分层、隔离、替身、门禁与覆盖率证据
依据 ADR：`docs/adr/0021-layered-deterministic-test-architecture.md`
关联测试：`tests/contract/test_test_suite_governance.py`

## 目的与边界

本标准定义 `tests/` 如何保护已经采纳的确定性契约。外部模型、提示词或候选解析路线是否值得采纳，
由[解析评测治理](../design/evaluation-governance.md)和冻结实验回答；测试不能替代评测，评测也不能
替代工程回归。可复制命令只在[开发指南](../guides/development.md)维护。

## 强制规则

### 测试分层

| 层级 | 职责 | 允许依赖 | 禁止事项 |
| --- | --- | --- | --- |
| `unit` | 业务规则、归一化、评分和错误处理 | 内存对象、确定性 fake | MySQL、进程、外部网络 |
| `contract` | 包依赖、文档治理、DesignRef 和设计语义 | 仓库源码与文档 | 运行数据库、业务工作流 |
| `integration` | MySQL、迁移、文件、HTTP 适配器和产物边界 | 隔离测试库、临时目录 | 运行库、外部模型 |
| `system` | 公开入口驱动的跨模块闭环和公开 fixture 回归 | 隔离测试库、假供应商 | 直接供应商调用、私有样本 |
| `smoke` | 独立 API/Worker 进程和实际装配入口 | 独立 smoke 库、回环网络 | 模型任务、公网、运行数据 |

测试文件只存在于上述五个目录并恰好获得一个同名 marker。`tests/support` 只保存复用辅助，不收集
测试；根 `tests/conftest.py` 负责收集期分层、网络隔离和唯一数据库 fixture，但数据库支持只能在
fixture 首次请求时延迟导入，模块加载不得导入生产应用或数据库驱动。共享辅助必须保持用途明确，
不能用万能 fixture 隐藏生产装配或业务入口。

### 隔离与替身

- 自动测试不得调用百炼或其他外部服务，不得要求模型密钥，不得写入 `data/` 或运行数据库。
- MySQL 测试只连接 `AXIOM_MYSQL_TEST_DATABASE`；库名与运行库相同立即失败，测试前后只清理
  `af_` 前缀表。
- smoke 使用单独配置的数据库，名称必须以 `_smoke` 结尾且不得等于运行库或普通测试库；schema
  只通过 Alembic 显式迁移。
- 系统测试使用确定性假供应商，但必须经过 HTTP、应用用例和 Worker，不得直接调用 repository
  伪装主链验收。
- 公开 fixture 回归可以检查文本、结构、公式、表格、图片、bbox 和 manifest；通过结论不得扩展为
  真实 OCR 质量背书。

### 门禁与覆盖率

- pull request 与 `main` 都必须执行静态检查、`unit + contract`、`integration + system` 和
  `smoke`；后一阶段不得掩盖前一阶段失败。
- 共享状态机、API、持久化或跨领域流程变更追加全量测试。正式发布仍按 D 类计划执行完整差异和
  人工复核。
- 覆盖率报告分别统计 `src/axiom_flow` 与 `evaluation`，作为盲区证据保存；当前不设置全局
  `fail-under`。覆盖率不能替代关键状态转换、错误路径、回滚和数据保护场景。

## 执行与门禁

1. 新测试先选择唯一层级，再在 code-map 和被测模块文件头登记稳定路径。
2. 定向测试使用目录或 marker 执行；数据库层和进程层失败必须与环境预检失败分开报告。
3. 可复现缺陷先补入相应层级的回归测试；外部质量失败进入评测或 tracker，不写成不稳定测试。
4. 移动或新增测试时运行测试套件治理、代码映射、文档链接和适用全量门禁。

## 变更与取代

改变五层职责、自动测试与评测边界、数据库隔离、外部网络禁令或 CI 必需阶段时必须先新增 ADR。
目录内普通测试增删、fixture 抽取和命令勘误属于实现同步，不单独建立治理 ADR。
