## 目的与边界

为探索项目提供从想法到关闭的轻量流程：按风险分级，多数任务无需重流程，破坏性/受保护操作
必须计划与备份。任务工作类型（A/B/C/D）与变更对象分级（见 `AGENTS.md`）正交，均须遵守。

## 任务分类

| 类型 | 适用 | 要求 |
| --- | --- | --- |
| A 类 | 日常小规模源码/文档/数据操作 | 无独立计划，git 提交与标签留痕 |
| B 类 | 新功能、重构、多步变更 | 建立计划文档（`docs/plans/`）、todo 登记、验收后关闭 |
| C 类 | 外部依赖、供应商选型、实验冻结 | 冻结假设/样本/预算/采纳门槛，结果经 ADR 接受后才成为设计 |
| D 类 | 正式发布、受保护环境、大规模数据操作 | 计划 + 备份 + 回滚 + 完整差异复核，不得隐式执行 |

## 任务台账与承载（ADR 0006）

**本节是台账口径的唯一正文**：列名、列界数值、禁词清单与守护判据只在这里维护。`todo.md` 的节首段与
「规则」节、`doc-governance.md`、本地技能一律**链接本节、不复制其口径**，防止同一规则长出一套以上说法。

- **列契约（[ADR 0013](../adr/0013-ledger-row-three-elements.md)）**：todo 表固定七列
  `ID / 类别 / 优先级 / 状态 / 任务 / 成功标准 / 承载`。三列各司其职，且**行内不写日期与现状**：
  - 「任务」＝**任务描述**：这件事到底做什么，按承载计划的「工作项」列出范围（哪几步、落哪个
    表/端点/模块），不写进度与裁决史，**也不放文档链接**（链接只在「承载」列出现）；跨项目入站请求的
    `**请求接收（来源仓库 REQ-xxx）**` 标记写在本列句首。
  - 「成功标准」＝**完成时的具体终态**：谁做什么、什么落哪张表/哪个端点/哪个产物，一句话可检验
    （≤80 字），读者不必打开别处文档就知道这件事交付什么。**一经评审固定，不随进度改写**；
    **禁写验收流程措辞**（守护禁词 `门禁`/`收口`/`全绿`/`成文` 与 `S1~S6` 形判据区间引用——它们属于
    计划壳「验证与验收」节）。写不出成功标准的诉求不得成为任务行。长期行写退出/立项条件，
    主线聚合行写其支线终态的合取。
  - 「承载」＝**唯一承载文档指针**：**恰好 1 个** markdown 链接、**不含自然语言**——计划镜像行指向
    其自身壳（链接文本＝壳 H1 标题，标题与 `状态：` 逐字同步由镜像守护断言）；支线行指向其
    `../plans/*.md` 承载壳（共享计划下的多个支线行可指向同一篇）；长期行指向其治理文档
    （`standards/` 或 `roadmap.md`）。`design/`、`architecture/` 文档**不在台账登记**，由承载文档自身的
    「关联设计／关联 ADR」元数据给出，避免同一事实在两篇文档间漂移；现状、裁决全文、勘察记录、门禁读数
    与执行日志一律活在承载文档里，关闭后的证据入 `completed.md`。
  - 守护判据：① 三列剥去 markdown 链接目标后不得出现 `\d{4}-\d{2}-\d{2}` 形式的日期字面量；
    ② 「承载」列剥去链接与分隔符后残余必须为空，且链接数**恰好为 1**；③ 「任务／成功标准」两列出现
    markdown 链接即转红；④ 「成功标准」列命中禁词即转红。
- **一任务一承载**（[ADR 0006](../adr/0006-ledger-plan-carrier-contract.md)）：每个支线行的承载
  计划引用**只写在「承载」列的那一个链接上**，且该计划「关联 Tracker」登记了本行 ID，或计划内含
  `## 承载 <本行ID>` 节（承载节四要素：目的、成功标准、工作项、状态）。主线聚合行免承载但必须
  列全支线行 ID；长期行免承载。A 类小改不入台账，以差异与验证记录承接。
- **一任务一行**（[ADR 0011](../adr/0011-ledger-one-row-per-task.md)，2026-10-01 用户裁决转正 Accepted）：跨项目入站请求与其专属承接计划不拆成两行，由计划镜像行单行承载
  （请求号写在「任务」列的请求接收标记内）；共享计划下的多个任务各自成支线行并引用同一承载。
- **进度单源**：日期化进度、现状与证据只写入承载文档；台账行不留现状叙述，收口时整行从 todo
  原子迁移到 `completed.md`（判据与读数在此安家），历史下沉承载计划「台账历史归档」节。
- **并发与规模**：支线行同时 `In Progress` ≤ 3（主线/长期行不计；超出须先收口或改判，用户可
  显式豁免）；同一主线活跃支线行 ≤ 8，超限触发一次合并/收口审视；「本轮主攻」全库唯一，登记
  在 `project-status.md`。进场（qed-intake）必须先声明本轮操作的行并检查上限。
- **DEFECT 前缀退役**：新缺陷登记为支线行并挂承载，不再新增 `DEFECT-*` ID；存量 DEFECT 行
  保留原 ID 至自然关闭（ID 永不复用原则不变）。

## 计划生命周期

1. **起草**：范围、步骤、验证、回滚、成功标准写入 `docs/plans/<日期-主题>.md`；轻量任务改用
   承载计划内的 `## 承载 <ID>` 节。
2. **登记**：计划行与任务行在 `docs/trackers/todo.md` 登记，保留原 ID，并把承载位置写成「承载」列
   的**唯一指针**（计划镜像行＝指向自身壳的链接）、声明成功标准；「任务」列只写范围，不放链接。
3. **评审**：用户确认计划正文（探索项目由用户直接确认，不设委员会）。
4. **执行**：日期化进度与证据只写入承载文档（工作项表/登记节）；todo 行不跟现状、不动成功标准，
   只有状态实际跨档时才改「状态」列三值。
5. **收口（顺序固定，缺任一项视为未收尾）**：① 结论写入承载文档 → ② todo 行压缩并关闭 →
   ③ 原子迁移 `completed.md`（证据在此安家）→ ④ `plans/index.md` 登记 Retain/Delete 去处 →
   ⑤ `project-status.md` 刷新 → ⑥ 全量门禁。

## 探索项目节奏

- 破坏性重构允许，但必须：先归档旧物（git mv/提交）、保留回滚点、逐轮小步推进。
- 外部模型/工具实验前必须冻结假设、样本、内容哈希、预算和采纳门槛。
- 不做委员会式评审；用户是唯一决策者。

## 执行与门禁

- 计划与任务台账变更后运行 `tests/contract/test_plan_governance.py` 与
  `tests/contract/test_tracker_governance.py`，再运行全量门禁
  （见[开发指南](../guides/development.md)）。
- 计划元数据、章节与关闭归档规则以[文档治理规范](doc-governance.md)为准。

## 变更与取代

改变任务分类、计划准入或关闭规则时必须先新增 ADR；措辞、链接和不改变语义的整理可直接修改。
