## 目的与边界

为探索项目提供从想法到关闭的轻量流程：按风险分级，多数任务无需重流程，破坏性/受保护操作
必须计划与备份。任务工作类型（A/B/C/D）与变更对象分级（见 `AGENTS.md`）正交，均须遵守。

## 任务分类

| 类型 | 适用 | 要求 |
| --- | --- | --- |
| A 类 | 日常小规模源码/文档/数据操作 | 无独立计划，git 提交与标签留痕 |
| B 类 | 新功能、重构、多步变更 | 建立计划文档（`docs/plans/`）、todo 登记、验收后关闭 |
| C 类 | 外部依赖、供应商选型、实验冻结 | 冻结假设/样本/预算/采纳门槛，结果经 ADR 接受后才成为设计 |
| D 类 | 正式发布、受保护环境、大规模数据操作 | 计划 + 备份 + 回滚 + 完整差异复核，不得隐式执行 |

## 任务台账与承载（ADR 0006）

- **列契约**：todo 表固定七列 `ID / 类别 / 优先级 / 状态 / 任务 / 关闭条件 / 证据/下一条件`。
  「任务」列写一句话目的（终态描述）；「关闭条件」为一句话可检验判据（≤80 字），写不出关闭
  条件的诉求不得成为任务行；「证据/下一条件」只保留最新一条结论 + 承载引用（≤200 字）。
- **一任务一承载**：每个支线行必须在「任务」或「证据/下一条件」列引用承载计划文件，且该计划
  「关联 Tracker」登记了本行 ID，或计划内含 `## 承载 <本行ID>` 节（承载节四要素：目的、关闭
  条件、工作项、状态）。主线聚合行免承载但必须列全支线行 ID；长期行免承载，「关闭条件」写
  退出/立项条件。A 类小改不入台账，以差异与验证记录承接。
- **进度单源**：日期化进度与证据只写入承载文档；todo 行收口时就地覆盖旧结论，历史下沉承载
  计划「台账历史归档」节与 `completed.md`，不在台账累积日志。
- **并发与规模**：支线行同时 `In Progress` ≤ 3（主线/长期行不计；超出须先收口或改判，用户可
  显式豁免）；同一主线活跃支线行 ≤ 8，超限触发一次合并/收口审视；「本轮主攻」全库唯一，登记
  在 `project-status.md`。进场（qed-intake）必须先声明本轮操作的行并检查上限。
- **DEFECT 前缀退役**：新缺陷登记为支线行并挂承载，不再新增 `DEFECT-*` ID；存量 DEFECT 行
  保留原 ID 至自然关闭（ID 永不复用原则不变）。

## 计划生命周期

1. **起草**：范围、步骤、验证、回滚、成功标准写入 `docs/plans/<日期-主题>.md`；轻量任务改用
   承载计划内的 `## 承载 <ID>` 节。
2. **登记**：计划行与任务行在 `docs/trackers/todo.md` 登记，保留原 ID，并声明承载位置与关闭条件。
3. **评审**：用户确认计划正文（探索项目由用户直接确认，不设委员会）。
4. **执行**：日期化进度与证据只写入承载文档（工作项表/登记节）；todo 行只反映最新状态结论。
5. **收口（顺序固定，缺任一项视为未收尾）**：① 结论写入承载文档 → ② todo 行压缩并关闭 →
   ③ 原子迁移 `completed.md`（证据在此安家）→ ④ `plans/index.md` 登记 Retain/Delete 去处 →
   ⑤ `project-status.md` 刷新 → ⑥ 全量门禁。

## 探索项目节奏

- 破坏性重构允许，但必须：先归档旧物（git mv/提交）、保留回滚点、逐轮小步推进。
- 外部模型/工具实验前必须冻结假设、样本、内容哈希、预算和采纳门槛。
- 不做委员会式评审；用户是唯一决策者。

## 执行与门禁

- 计划与任务台账变更后运行 `tests/contract/test_plan_governance.py` 与
  `tests/contract/test_tracker_governance.py`，再运行全量门禁
  （见[开发指南](../guides/development.md)）。
- 计划元数据、章节与关闭归档规则以[文档治理规范](doc-governance.md)为准。

## 变更与取代

改变任务分类、计划准入或关闭规则时必须先新增 ADR；措辞、链接和不改变语义的整理可直接修改。
