# 文档规范

状态：Current
最后更新：2026-08-14

## 目的与边界

本规范定义文档分类、命名与元数据规则，保证仓库文档可定位、可追溯。探索项目要求文档精简：
只保留必要任务与必要设计，不维护模板目录。

## 文档分类与事实边界

| 位置 | 唯一职责 |
| --- | --- |
| 根 `README.md` | 项目定位、能力、技术栈和快速启动。 |
| 根 `AGENTS.md` | Agent 执行总纲：目标、任务路由、问题定位与完成检查。只指引，不保存正文事实。 |
| `docs/index.md` 与各目录 `index.md` | 只导航当前文件，不保存正文事实。 |
| `architecture/` | 当前系统结构、运行拓扑和代码映射。 |
| `design/` | 当前流程、接口、状态、失败语义、质量门槛和验收契约。 |
| `adr/` | 影响长期约束的决定、理由、后果和取代关系。 |
| `standards/` | 工程治理规则。 |
| `guides/` | 当前可重复执行的开发与运维步骤。 |
| `plans/` | 已批准且尚未关闭的短期执行合同。 |
| `trackers/` | 全部未关闭任务和简短关闭台账。 |
| `history/` | 选择性保留的归档证据和旧基线。 |

一个事实只设一个维护位置，其他文档使用链接。

## 写作、命名与索引

- 中文说明使用短句和明确主语；标识符、API 字段和外部协议名称保留英文。
- 文件名使用小写英文和连字符；活跃架构、设计、标准和指南使用稳定名称，不绑定产品版本。
- 文档目录入口统一为小写 `index.md`；`docs/**/README.md` 禁止存在。
- 内部链接显式指向文件或 `index.md`。
- Mermaid 图与说明在同一正文维护，不提交派生图片。

## 元数据

架构、设计和 ADR 声明：设计状态、实现状态、最后更新、关联代码、关联测试和关联 ADR（无则
写"无"）。索引文档只声明状态与最后更新。

## 归档与删除

被取代的文档移动到 `history/` 对应分类，不就地删除；git 历史是最终回滚保证。归档时保留
原文件头（git mv 后追加归档说明或经 history 索引标注即可）。

## 执行与门禁

- 新增或改动活跃架构/设计/ADR 后，运行对应契约测试与全量门禁（`pytest tests -q` +
  `ruff check src tests`）。
- 文档与代码追溯（DesignRef、code-map）变更后运行映射契约测试。
