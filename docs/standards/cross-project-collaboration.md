# 跨项目协作流程

状态：Current
最后更新：2026-08-10
治理对象：跨项目需求的接收、评审、执行与验收回执
依据 ADR：`docs/adr/0015-standards-as-governance-source.md`、`docs/adr/0017-consolidated-task-ledgers-and-roadmap.md`
关联测试：`tests/contract/test_cross_project_collaboration.py`

## 目的与边界

本标准规定 Axiom-Flow 与 QED-Engine 根仓库、QED-Tracker 之间协作需求如何接收、评审、执行与
回执。三个项目是独立 git 仓库，各自独立开发、独立部署；任何跨项目改动必须由目标项目在其仓库
内完成并遵守其门禁，本仓库不直接修改其他仓库文件。

适用范围：任何需要配合的跨项目改动（服务端口、数据目录、直读配置变量、接口对接、前端迁移、
治理范本对齐等）。纯本仓库内的改动不适用本标准，走[任务生命周期](task-lifecycle.md)。

## 强制规则

### 流程步骤

1. **接收登记**：根仓库发起请求（REQ-xxx）后，本仓库在 `docs/trackers/todo.md` 以稳定 ID
   （ALN-xxx）登记承接行；任务列说明承接事项，证据/下一条件列记录发起方与编号（如
   「QED-Engine 发起（根仓库 REQ-xxx）」）。
2. **评审**：用户评审需求方向与相关设计文档后确认；确认前不执行。
3. **执行**：按[变更规模分级](#变更规模分级)选择计划类型，在本仓库内完成并遵守本仓库门禁。
4. **验收回执**：执行完成并关闭本仓库 todo 后，把回执证据（提交号、门禁输出）交由根仓库更新
   其 REQ 任务状态；本仓库 todo 证据列同步记录。
5. **约束**：跨项目改动不得破坏独立性铁律；根仓库总台账与本仓库 todo 保持镜像一致。

### 变更规模分级

| 规模 | 判定 | 必须产出 |
| --- | --- | --- |
| 接口/契约级 | 协议、端口、地址、字段、数据目录或配置事实源变化 | 本仓库设计文档 + todo 请求行 + 根仓库登记 |
| 文案/操作级 | 文档措辞、命令示例、默认值说明 | 仅 todo 登记，可并入其他任务 |

### 设计文档模板

承接接口/契约级请求时，在本仓库 `docs/design/` 建设计文档并声明：需求方、目标项目、接口面
（端口/变量/目录/协议）、评审方（用户）、执行方（本仓库）与验收标准。

### 登记格式

todo 承接行：任务列说明承接事项并标注根仓库编号（REQ-xxx）；证据/下一条件列记录发起方、
用户确认日期与执行计划承接情况。

## 执行与门禁

- 跨项目请求按任务生命周期分类：接口/契约级使用 B 类（或按规模 D 类）计划执行，文案级并入
  原任务。
- 请求被否决或改期时，本仓库 todo 行更新为 Blocked 并声明证据、恢复条件与责任位置。
- 本条流程由 `tests/contract/test_cross_project_collaboration.py` 守护登记格式与设计文档模板
  的一致性；具体跨项目事实以双方 todo 与 Git 历史为准。
- 回执证据（提交号 + 测试输出）写入本仓库 todo 证据列，并由根仓库在其 REQ 行记录。

## 变更与取代

改变流程步骤、变更分级或登记格式时必须先新增 ADR。措辞、链接和不改变语义的流程整理可直接
修改本标准。上游约定以根仓库 `docs/standards/cross-project-collaboration.md` 为准，本仓库为
承接侧适配。
