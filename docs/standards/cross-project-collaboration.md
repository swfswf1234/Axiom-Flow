# 跨项目协作流程

状态：Current
最后更新：2026-08-16

## 目的

规定本仓库（Axiom-Flow）agent 与 QED-Engine 根仓库、QED-Tracker 之间的工作区边界，
以及跨项目请求的评审、执行与回执路径。本仓库是独立 git 仓库，agent 的合法工作区
只限于本仓库；对根仓库与 QED-Tracker 一律只读，防止越界写入（2026-08-16 根仓库侧
误建 V2-003 代码事件后双向强化）。

## 工作区边界

| 对象 | 位置 | 本仓库 agent 动作 |
| --- | --- | --- |
| 本仓库 | `D:\coding\QED-Engine\Axiom-Flow` | 全部读写（代码/文档/测试），遵守本仓库 AGENTS.md 与门禁 |
| QED-Engine 根仓库 | `D:\coding\QED-Engine` | **只读**：理解 API 契约、integration-matrix 联调矩阵、协作上下文 |
| QED-Tracker | 同级子仓库 | **只读**：不参与其开发 |

- 只读范围包括：读取文档/代码/测试、运行只读命令；禁止任何文件写入与 git 写操作。
- **用户口头指令不豁免**：「改造/优化 QED-Engine（或 QED-Tracker）某服务」等指令仍受本
  边界约束——对根仓库的代码改动必须由根仓库自身执行，本仓库只能在其 todo 登记请求
  （经用户转达）或等待对方请求。
- 若误写入根仓库工作区（如误编辑其文件），必须立即停止、在 `docs/trackers/todo.md`
  登记移交说明并请求用户协助回滚，不得静默处理或提交。

## 接收跨项目请求（根仓库 → 本仓库）

1. **来源**：根仓库 `docs/trackers/todo.md` 登记（标注「请求：Axiom-Flow」）、
   `docs/design/integration-matrix.md`（C 组 8900↔8902），或根仓库在本仓库 todo 上的
   移交/前置标注（如 V2-003 越界产物移交、V2-004/005/007 联调前置请求）。
2. **评审**：接到请求先评审方向与范围，向用户确认后执行；用户是唯一决策者，agent
   不擅自接受或扩大外部请求范围。
3. **执行**：在本仓库按任务生命周期（A/B/C/D 类）推进，遵守本仓库门禁
   （`pytest tests -q` + `ruff check src tests`）。
4. **回执**：完成后更新本仓库 todo（证据：测试输出、commit）；根仓库自行读取并登记
   回执，本仓库不直接写根仓库文件。

## 发起跨项目请求（本仓库 → 根仓库）

需要根仓库配合时（如 v2 契约冻结后根仓库 REQ-034 适配）：

1. 在本仓库 `docs/trackers/todo.md` 登记请求条目（标注「请求：QED-Engine」），写明
   接口面（端口/字段/数据目录/协议）。
2. 将请求转达用户，由用户在根仓库登记或交由根仓库 agent 承接（本仓库不写根仓库文件）。
3. 根仓库回执后，本仓库验收并关闭对应条目。

## 执行与门禁

- 跨项目协作不破坏独立性铁律：根仓库离线时本仓库独立开发、独立部署。
- 本流程由 `tests/contract/test_standard_governance.py` 守护标准目录登记一致性；
  具体跨项目事实以双方 todo 与 git 历史为准。

## 变更与取代

改变流程步骤或边界规则时必须先新增 ADR；措辞、链接和不改变语义的整理可直接修改
本标准。上游约定以根仓库 `docs/standards/cross-project-collaboration.md` 为准，冲突时
以更严格的边界为准。
