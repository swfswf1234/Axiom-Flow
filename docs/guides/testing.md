# 测试指南

状态：Current
最后更新：2026-07-29

每个计划必须在实施前明确验证命令、验收样本和关闭门槛。评测用于决定模型或方案是否
值得采纳；测试用于保护已采纳实现，二者不能相互替代。

新架构的最低测试层次为：

1. 单元测试：路由、统一输出、质量规则、Excel 校验和版本状态机。
2. 集成测试：PDF 到规范化内容、审阅结论到知识候选、工作簿导入到发布快照。
3. 样本回归：文字型、扫描型、公式密集、表格/图示和失败样本。
4. 任务测试：幂等入队、双 Worker 互斥、租约恢复、取消、重试和任务级预算。
5. 协议测试：API v1 的 `202`、统一错误、上传边界和静态工作台。

v0.2 集成测试连接 `axiom_flow_test`，在不存在时创建它、执行 Alembic 迁移，并在每个测试
前后清空 `af_` 表。测试库名与运行库相同会立即失败；测试不得连接 `xqfm11` 的运行表。

文档或受管代码改动时，必须运行 `python -m pytest tests/test_code_document_mapping.py -q`；
该测试校验 `code-map.md`、模块文件头与活跃设计文档元数据的一致性。

历史测试命令与 MinerU 基线一同归档，不代表当前可执行命令。实现每个阶段后才将已验证
的命令写入本文件。

推送前还必须执行 `python -m ruff check backend evaluation tests`。GitHub CI 使用 MySQL 8
服务执行同一静态检查和全量测试，不调用百炼。

任务关闭采用分层门禁：所有任务通过定向测试和文档验收；修改共享模型、状态机、路由或
跨领域流程时追加回归；阶段完成时追加固定样本端到端验收。可复现失败必须登记到
[`../trackers/regressions.md`](../trackers/regressions.md)，修复时增加对应自动化测试；不能自动化的
外部依赖失败必须在评测报告中标注原因。
