# ADR 0018：台账「任务」列的列界与进度措辞禁词（把 ADR 0013 的口头约束收成可判据）

状态：Accepted
最后更新：2026-10-23
关联代码：`docs/trackers/todo.md`（表列；其「规则」段与节首只链接标准正文）、
`docs/standards/task-lifecycle.md`（列契约的**唯一正文**，本决定改的是那一节）
关联测试：`tests/contract/test_tracker_governance.py`（新增列界与禁词、禁裁决序号两条断言）

## 背景

[ADR 0013](0013-ledger-row-three-elements.md) 决定 1 把「任务」列定为**任务描述**并写明「不写日期与
进度，不放任何文档链接」，但落地时只把其中两半变成了判据：**禁 markdown 链接**与**禁 ISO 日期字面量**
由守护断言，「不写进度」没有对应判据——既没有列界，也没有禁词。后果在 2026-10-23 的收口轮实测暴露：

1. **单行膨胀到 2457 字**：PLAN-024 的「任务」列在十余个落地轮次里被当成跨窗口交接面板，每完成一项
   就往行尾追加一段，累积写成 `W3 已执行（…）＋W11／W12 已执行（…）＋W4~W7 已落地（…）＋W14 已执行
   （…）＋W8 已执行（备份 sha256、DROP 清单、空窗 11 条 GET 读数、回灌 17 本…）＋待用户逐条了结＝零项
   （裁决⑮⑯⑰⑱⑲⑳ 摘要）`。同一批事实**在本壳「工作项」表与「用户裁决」表里逐条更详细地已经存在**，
   于是行与壳构成第二事实源——正是 ADR 0013 背景 1 判过的那种漂移，只是这次漂在「任务」列。
2. **退化不可判出**：全量门禁在该行 2457 字的状态下始终绿（`test_tracker_governance.py` 对「任务」列
   只有无链接与无日期两条），所以「约定有、判据无」不是假设，是实测：同一轮里「成功标准」列超 80 字
   或命中禁词会立刻转红，而长度翻三倍的「任务」列不会。
3. **同类残留**：PLAN-018 行 563 字内混有 `进度＝W2 已落地…当前在 W3`，其落地细节同样已在自己的壳
   「W1 落地结论」「W2 落地结论与偏差登记」两节成文。

## 决定

1. **「任务」列设列界＝600 字**（含 markdown 标记与空格，与「成功标准」列 80 字同一算法：`len(cell)`，
   剥不剥链接目标都满足），超限即转红。定档依据＝本案最长范围列表的实际需要：14 个 W 步骤名＋目标
   形状关键列，压缩后实测 586 字；留约 2% 余量给步骤名增删，不给叙述留余量。
2. **「任务」列禁进度措辞**（守护禁词，与「成功标准」列的验收流程禁词分列各自维护）：
   `已执行`、`已落地`、`已完成`、`当前在`、`进度＝`、`已了结`、`待裁`。判据取「描述范围时不需要、
   描述进度时必然出现」这一侧：范围句写「W8 档 B 真机整族重建窗口（D 类）」，进度句写「W8 已执行
   （…读数）」，两者只差那一个词，故词表可机械判定。
   另禁**裁决序号引用** `裁决[①-⑳]`（裁决史属于壳的「用户裁决」表；写「按用户裁决」这类无序号措辞
   不在禁止之列）。
3. **唯一正文仍是一处**：列界数值与禁词清单只写在
   [任务生命周期](../standards/task-lifecycle.md)「任务台账与承载」，本 ADR 只作决定记录，
   `todo.md` 节首段与本地技能一律链接该节、不复制数值（ADR 0013 后果「缓解」条的纪律不变）。
4. **实施按先红后绿＋变异复验**：先加断言使当代存量行转红（两条实测红＝PLAN-024 以 918 字触发列界、
   PLAN-018 以 `已落地／当前在／进度＝` 触发禁词），再逐行瘦身到绿；瘦身前先在各自壳确认被删事实
   已有归属（补前删：两行共丢弃 9 枚反引号 token，逐枚在其承载壳内命中）。变异复验三条＝往任一行
   注入一段 `已执行` 措辞、把任一行顶到 601 字、注入一枚 `裁决⑲` 序号，各转红一次后当场还原。

## 后果

- **正面**：「任务」列的三条约束（无链接、无日期、无进度）第一次全部可机械判定，行膨胀会在注入的
  那一次提交就转红，而不是等到有人读表时才发现；台账回归纯导航——「做什么／完成时长什么样／去哪读」，
  粗粒度进度仍只有「状态」列三态。
- **代价**：① 600 字对**步骤极多的壳**是硬约束，超出时必须把步骤名压成一行一个短语（这是本决定的
  目的，但确实牺牲行内可读细节）；② 禁词表按中文措辞判定，误伤面存在——「已完成人工确认门的端点」
  这类描述范围的写法会因 `已完成` 转红，须改写措辞而不是申请豁免；③ 存量历史文档（`completed.md`
  已关闭行、归档壳、`project-status.md` 各轮叙述）仍含此类措辞，**不随本决定回改**（当时记录）。
- **缓解**：`project-status.md` 仍是现状快照的唯一位置，进场读表拿不到进度时按 ADR 0013 的既定设计
  打开唯一承载文档；禁词与列界只作用于 `todo.md` 的「任务」列，壳内「工作项」状态列与回执照旧写
  「已执行」，不受本决定约束。

## 取代

取代：无。本决定是 [ADR 0013](0013-ledger-row-three-elements.md) 决定 1「不写日期与进度」与决定 4
「守护落地」四件事的**收紧与补齐**（把其中「不写进度」由措辞升为判据），不改变三列语义、列名、
唯一指针判据与成功标准列的既有禁词；ADR 0006 的「进度单源」继续有效，本 ADR 只是让它可守护。
被取代：无。
