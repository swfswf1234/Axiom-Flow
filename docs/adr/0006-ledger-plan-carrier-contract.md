# ADR 0006：任务台账与计划承载契约（一任务一承载、进度单源、并发上限）

状态：Accepted
最后更新：2026-10-01
关联代码：无（流程治理，不映射具体模块）
关联测试：`tests/contract/test_tracker_governance.py`、`tests/contract/test_plan_governance.py`

## 背景

现行任务生命周期与台账规则存在结构性缺陷，导致进度事实散落在 todo 行、计划正文与
project-status 三处，且任务不可验收、收尾不清理：

1. **进度双事实源是规则逼出来的**。todo 规则要求「证据/下一条件」列按 `**YYYY-MM-DD 事件**`
   追加日期化事实且不改写历史，而计划规则禁止逐日工作日志——两者叠加的必然结果是：进行中
   任务的日志只能在 todo 行里膨胀（PLAN-002/003 行已达 800+ 字，镜像并超出计划正文）。
2. **多数任务行无承载文档且合规**。task-lifecycle 只要求 B 类建计划，qed-intake 甚至写明
   缺陷「不单独建计划」；因此 DEFECT、ARCH 支线与 REQ 行大量处于「进度无处沉淀」状态，
   细节最终散写进别的计划或 todo 行。
3. **任务不可验收**。没有规则要求每行声明可检验的关闭条件；「完成」无判据，收尾自然无从谈起。
4. **并发无约束、收口无触发**。多个 In Progress 行长期并存，文档治理的「主线任务完成后梳理」
   只挂在版本末期（ARCH-010），日常收口不清理 todo 镜像劣化。
5. **skill 引用悬空**：qed-intake 指向 task-lifecycle 不存在的「缺陷处理」节；qed-plan 与
   doc-governance 的计划命名规则互相矛盾。

用户裁决（2026-09-21）：不强制「一 todo 行 = 一计划文件」；允许多任务并行但需设上限；
DEFECT 前缀为历史遗留，不再新增，存量保留至自然关闭。

## 决定

1. **职责切分**：todo 行只回答「做什么、为了什么目的、现在到哪/卡在哪」；承载文档
   （`plans/` 计划文件或计划内专属承载节）回答「怎么做、做到哪了、证据是什么」。
   所有日期化的执行进度与证据只写入承载文档，todo 行不记过程。
2. **一任务一承载**：除主线聚合行外，每个 todo 行必须恰好声明一个承载位置——一个计划文件，
   或某计划内的承载节（承载节须含：目的、关闭条件、工作项表、状态）。主线聚合行免承载，
   但必须在行内列全其子任务行 ID；子任务不得只存在于聚合行叙述中。
3. **关闭条件成文**：todo 表新增「关闭条件」列，一句话可检验判据；写不出关闭条件的诉求
   不得成为任务行，只能作为某计划的工作项或非目标。
4. **证据列瘦身与可覆盖**：「证据/下一条件」列只保留最新一条状态结论 + 指向承载位置的
   引用，长度上限 200 字；**取代**原「按日期追加、不改写历史」规则——历史结论的归宿是
   承载文档与 completed.md 证据列，todo 行允许就地覆盖。
5. **并发与规模上限**：支线行同时 `In Progress` ≤ 3（主线聚合行不计入；用户显式豁免可超）；
   同一主线活跃支线行 ≤ 8，超限触发一次合并/收口审视；`project-status.md`「当前主线」中
   全库唯一的本轮主攻行。进场（qed-intake）必须先声明本轮操作的行并检查上限。
6. **DEFECT 前缀退役**：不再新增 `DEFECT-*` 行；新缺陷登记为支线任务行并挂承载（前缀按
   所属域就近选择，已有 ID 永不复用的原则不变）。存量 DEFECT-001/006/007/008 保留原 ID
   直至自然关闭。
7. **A 类不入台账**：一行内可完成、以 git 提交即可留痕的 A 类小改不建 todo 行（维持
   AGENTS.md 豁免原则并显式成文），防止台账灌满。
8. **收口清单固定顺序**（qed-closeout 承接）：① 结论写入承载文档（计划状态或承载节收口）→
   ② todo 行压缩为一句话结果 + 关闭 → ③ 迁移 completed.md（证据在此安家）→
   ④ `plans/index.md` 登记 Retain/Delete 去处 → ⑤ `project-status.md` 按需刷新 →
   ⑥ 全量门禁。①~④ 缺任一项视为未收尾。
9. **规则同步面**：本决定落地需同步 `standards/task-lifecycle.md`、`doc-governance.md`
   （计划命名统一为 `YYYY-MM-DD-<类型>-<slug>.md`，以现存文件为准）、todo「规则」节、
   qed-intake/qed-plan/qed-closeout 技能正文，并由契约测试守护（承载引用存在、关闭条件
   非空、证据列长度与 In Progress 计数上限、镜像校验扩展至承载节）。

## 后果

- 正面：每任务可验收、进度单源、todo 恒为一屏导航；收尾有机械判据，skill 与测试不再留空档。
- 代价：任何状态变化都要先动承载文档（一次任务两处编辑）；存量 todo 行需要一轮压缩改造。
- 缓解与风险：多任务并行（如与根仓库联调）受 ≤3 约束，靠用户显式豁免兜底；承载节若游离于
  计划标题层级约定外，锚点会失效——由契约测试校验引用存在性兜底。

## 取代

取代：无（修订 [任务生命周期](../standards/task-lifecycle.md) 与
[文档治理规范](../standards/doc-governance.md) 的台账与进度规则条文，不改其分类框架）。
被取代：决定 2/3/4 的台账**列名与列语义**（「关闭条件」列、「证据/下一条件」列及其列界）被
[ADR 0013](0013-ledger-row-three-elements.md) 取代（2026-09-30，七列三要素形态）；其余决定
（一任务一承载、进度单源、并发上限、DEFECT 退役、收口顺序）继续生效。现行台账口径的唯一正文是
[task-lifecycle「任务台账与承载」](../standards/task-lifecycle.md)，本 ADR 保留为决定记录；
正文中的旧列名按当时形态读。
