# ADR 0011：台账一任务一行（入站请求与其专属承接计划合并为单行）

状态：Accepted
最后更新：2026-10-01
关联代码：无（台账治理，不映射具体模块）
关联测试：`tests/contract/test_tracker_governance.py`（计划镜像唯一性与承载引用守护）

## 背景

1. **同一任务两行是实测缺陷**：REQ-097/PLAN-017 与 REQ-099/PLAN-018 曾各按「请求接收支线行 +
   计划镜像主线行」两行登记同一件事，两行的任务描述、关闭条件与证据互相复制，改一处必漏另一处
   （2026-09-26 用户指出不符合「一个 todo 任务对应一个 `plans/` 文档」的预期）。
2. **既有契约没禁但它留了口子**：[ADR 0006](0006-ledger-plan-carrier-contract.md) 决定 2 只要求
   「每行恰好一个承载位置」，未规定「每任务几行」；其背景节记录的 2026-09-21 裁决「不强制
   一 todo 行 = 一计划文件」放宽的是**多任务共享计划**，不授权把同一任务拆成两行。
3. **守护已把可行形状钉死**：`test_todo_plan_rows_exactly_mirror_active_plan_bodies` 要求每个活跃
   计划在 todo 恰有一行「任务」列为纯计划链接的镜像行，且行状态与计划正文 `状态：` 逐字一致。
   故「一任务一行」的唯一可行落点是**保留计划镜像行**，请求号降为来源标注；把镜像行改成
   `REQ-*` 会让该行状态落入 `Accepted`，与台账「支线行状态只用 Open/In Progress/Blocked」冲突。
4. **请求号的可追溯性不能丢**：根仓库按 REQ 号读回执，本仓库台账仍需机械检索到该号。

## 决定

1. **专属承接合并为单行**：入站（或出站）跨项目请求，若其承接工作是**为该请求单立的专属计划**，
   台账只保留该计划的镜像行（`PLAN-*`，类别 主线），不再另立 `REQ-*` 支线行。请求号写在该行
   「证据/下一条件」列的 `**请求接收（来源仓库 REQ-xxx）**` 标记内，并保留在计划正文的
   「关联 Tracker」「归档判定」与回执节中。
2. **共享计划不变**：请求由既有计划或共享计划承接时，仍按 ADR 0006 登记 `REQ-*` 支线行并引用
   同一承载（该计划「关联 Tracker」登记本行 ID，或含 `## 承载 <本行ID>` 节）——「多任务一计划」
   合法，「一任务两行」不合法。
3. **合并不留尾巴**：并行为单行时就地压缩——关闭条件取两行判据的交集写成一句话（≤80 字），
   证据列只留最新结论 + 承载引用（≤200 字）；不新增 `completed.md` 行（任务未关闭），不注销编号
   （该 `REQ-*` 号在本仓库不再成为行 ID，视同未使用，ID 永不复用原则不变）。
4. **规则同步面**：`standards/task-lifecycle.md`「任务台账与承载」与 todo「规则」节各新增
   「一任务一行」条并引用本 ADR；镜像行的状态一致性继续由既有契约测试守护，本决定不新增测试。

## 后果

- **正面**：一个任务＝一个台账行＝一个承载，状态与判据单源；请求号仍以纯文本可检索，根侧回执
  路径与判据不变。
- **代价**：台账不再以 `REQ-*` 行罗列入站请求清单，请求盘点要读各计划镜像行的证据列或计划的
  「关联 Tracker」；`REQ` 前缀的可见度下降。
- **缓解**：计划壳的「归档判定」与回执正文保留根侧请求号，`docs/plans/index.md` 与
  `project-status.md` 的承接项叙述同样标注请求号，盘点用 `rg "REQ-"` 即可全覆盖；若未来需要
  一张入站请求清单，应在 `project-status.md` 或固定文档中成文，而不是回退到双行台账。

## 取代

取代：无（细化 [ADR 0006](0006-ledger-plan-carrier-contract.md) 决定 2 的推论，不改其承载契约框架，
也不推翻「不强制一 todo 行 = 一计划文件」的既有裁决）。
被取代：决定 1/3 里的「证据/下一条件」列与列界措辞被 [ADR 0013](0013-ledger-row-three-elements.md)
的七列台账取代（2026-09-30）——请求接收标记现落在「任务」列句首，「一任务一行」的现行口径以
[task-lifecycle「任务台账与承载」](../standards/task-lifecycle.md) 为唯一正文，本 ADR 保留为决定记录。
状态流转：Draft（2026-09-26）→ Accepted（2026-10-01，用户裁决转正；规则已于 2026-09-26 起在
`task-lifecycle.md` 与守护测试中生效执行）。
关联：[ADR 0008](0008-fixed-doc-form-and-metadata-genres.md)（固定文档骨架与元数据）；
